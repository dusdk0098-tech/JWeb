# 남은 기능 영역 사양안 (기타 항목 승인 후 1단계: 사양 확정)

**상태:** 2026-10-31 사용자가 "기타 항목"을 승인했다. 인계문서(01_IMPLEMENTATION_GUIDE §3·§4·§7·§10, 02 요구 표)는 이 영역들을 **사양·근거 확정 뒤** 구현하라고 정했다. 이 문서는 영역마다 인계문서의 [제안]을 첫 수직 구현 단위로 좁히고, 구현 전에 사용자가 정해야 할 값을 모은다. 아래 "결정 필요"가 채워지는 영역부터 하나씩 구현한다.

권장 순서: ① MOB-01(QR 참여, 공학 근거 불필요) → ② P-01(문서 1종씩) → ③ SC-04(AI, 끈 상태 기본) → ④ 오프라인 → ⑤ WEB-01 → P-02(전문가 검토 후).

## ① MOB-01 — QR 참여·직접 서명·동의 위치

**1단계 구현(2026-10-31, 본인 확인 = 이름+생년월일 결정):** schema 63 `worker_identities`(생년월일은 scrypt 솔트 해시만), `activity_invitations`(토큰 해시만, 2시간 만료, 1회 폐기, TBM 내용 hash 결속), `participation_events`(추가 전용, 초대·인원당 1건). 관리자가 명부에서 생년월일 등록 → TBM 편집에서 "참여 링크 만들기"(토큰은 URL `#` 뒤에만, 서버 로그 미전달) → 근로자가 로그인 없이 `/join`에서 이름+생년월일 확인 → 참여 기록. TBM 참석 상태는 자동으로 바뀌지 않는다. 잘못된 시도는 링크당 15분 10회 제한. QR 이미지: 사용자 승인으로 `qrcode` 1.5.4(MIT) 추가, 링크 발급 시 화면에 QR 표시. **2단계("권장대로" 결정):** schema 64 `consent_records`·`signature_records`(추가 전용, 3년 보존일 기록). 참여 화면에서 동의문(v1, 2026-10-31 소유자 확정)을 보고 손서명 후 제출하거나, 동의하지 않고 참여만 기록. 서명 PNG는 TBM 문서 hash에 결속, 관리자 화면에서 확인. 위치 확인은 권장대로 하지 않음. 3년 경과 파기 절차는 2028년에 정한다(2026-10-31 결정, 첫 만료 2029년). 남은 것: **실제 휴대폰 사용은 이 앱이 127.0.0.1에만 열려 있어 운영 배포(HTTPS·네트워크) 승인 전에는 불가.**

**3단계 구현(2026-11-10, PR #111):** 같은 초대·참여·동의·서명 구조를 교육일지에 적용(schema 81, 두 표의 CHECK를 넓히려 재구성). 교육일지 초대는 내용에만 결속해 참석 표시 뒤에도 유효하고, 참여 기록은 `education_participants`를 바꾸지 않는다(참석·참여시간은 작성자가 직접 기록, 이수 판정 아님). 동의문은 2026-11-12 `education-signature-v1`로 확정. 남은 것: 출역 QR(문서가 아니라 날짜 단위 행이라 결속 기준부터 정해야 함), 실기기.

- **첫 단위:** TBM 1종에 대해 관리자가 만료 있는 QR 초대를 발급 → 근로자가 앱 설치 없이 열어 이름 확인 → "참여 기록"을 남긴다. 서명·위치는 2단계.
- **설계(인계 [제안] 그대로):** `activity_invitations`(현장·활동·문서 hash·만료·폐기), `participation_events`(대상·행위·시각·문서 hash). 원래 토큰은 hash만 저장하고 URL 로그에 남기지 않는다. QR만으로 신원·참석 완료를 증명하지 않으며, TBM 명부 반영은 관리자가 명시적으로 고른다.
- **결정 필요:**
  1. 본인 확인 수준: 이름+생년월일 끝자리 / 명부 선택만 / 휴대폰 인증(외부 서비스, 비용·개인정보 승인 필요).
  2. 초대 만료 시간 기본값(예: 2시간)과 1회용 여부.
  3. 대리 입력 허용 여부와 표시 방법.
  4. 동의문 문구·보존기간(서명·위치 단계에 필요).

## ② P-01 — 작업계획 문서 확장

**1단계 구현("권장대로"):** 원본 P 상세설계(`pedit-p-source` docs/DETAILED-DESIGN.md, src/shared/form-modules.ts)를 읽기만 하여, 아직 없던 계산 없는 유일한 문서인 원본 시트 1 "양식사용 체크리스트"를 추가했다. 17개 양식 모듈(정책 FORM-POLICY-2026.07.1)의 포함 여부·메모를 작업계획별로 저장(schema 65 `work_plan_form_checklists`, 작성자·작성 중에만 수정, 보관 후 고정)하고 인쇄한다. 필수 2종(일반 작업계획·위험요인 참고)은 제외 불가. 나머지 계산 양식(시트 3·5·14~20)은 P-02 전까지 보류.

- **첫 단위:** 원본 17종 중 1종을 골라 입력·단위·필수조건·출력 영역을 대조표로 만든 뒤 strict discriminated union 한 종류로 추가한다(기존 `general_machine`·`excavator_lift`와 같은 방식). 계산·안전 판정 없음.
- **결정 필요:**
  1. 첫 문서 종류(원본 P 앱의 17종 목록에서 선택).
  2. 원본 P 소스 위치(로컬 `pedit-p-source` 등) 사용 승인.

## ③ SC-04 — 선택형 AI

**1단계 구현("권장대로"):** 비용 지출 입력의 "내용" 옆 [AI 문구 제안]. 기본 꺼짐 — `.env`에 `AI_ENABLED=true`와 `AI_MONTHLY_REQUEST_LIMIT`(월 요청 수 상한, 금액 상한 대신)가 모두 있어야 켜진다. 공식 SDK `@anthropic-ai/sdk` 1.3.0(Apache-2.0)으로 Claude(`claude-opus-5-5`, `AI_MODEL`로 변경 가능, effort low, 안전 거절 시 서버 측 fallback)에 내용 문구만 보낸다(3자리 이상 숫자는 `#`). 제안은 보여 주기만 하고 사용자가 [제안 적용]을 눌러야 입력칸에 들어간다. 관리자만, 월 사용량 기록(schema 67 `ai_usage`). 실제 API 호출은 시험하지 않았다(키·상한 미설정). 남은 것: 월 상한 값 결정, 실제 호출 확인.

- **첫 단위:** 끈 상태가 기본인 "지출 내역 문구 제안" 1기능. 사용자가 버튼을 누를 때만 실행하고, 결과는 diff로 보여 준 뒤 사용자가 적용한다. 원장 변경·마감·회계 판단은 하지 않는다. AI를 꺼도 모든 기능이 동작해야 한다.
- **결정 필요:**
  1. 제공자·모델(예: Anthropic Claude)과 API 키 보관 방식.
  2. 외부로 보내도 되는 필드(지출 내용만? 금액 포함?)와 개인정보 제외 규칙.
  3. 월 비용 상한.

## ④ 오프라인 초안·동기화

**1단계 구현("권장대로"):** 안전업무일지 편집 중 입력이 서버 저장본과 다르면 0.8초 뒤 이 기기 IndexedDB에 Web Crypto AES-GCM(256, 추출 불가 키)으로 암호화 보관한다. 통신이 끊겨 저장이 실패하면 그 사실을 알리고, 다시 열 때 "기기 초안 복원/버리기"를 고르게 한다(자동 덮어쓰기 없음, 서버 저장은 기존 버전 검사). 서버 저장 성공 시 삭제, 7일 경과 시 삭제, 로그인·로그아웃 때 전체 삭제(키도 새로 생성). 서버 DB 변경 없음. 남은 것: 다른 업무 화면, 백그라운드 자동 재전송(outbox), 기기 철회.

**2단계:** TBM·점검(이후 신고·조치) 편집에도 기기 초안, 연결 복구 시 열려 있는 편집 화면이 한 번 자동 저장.

**3단계 구현(2026-11-10, PR #112) — 전송함:** 통신 두절로 실패한 저장을 같은 IndexedDB(버전 2, `outbox` 저장소)에 암호화해 넣고 연결 복구·앱 시작·수동으로 차례로 보낸다. 편집 화면이 닫혀 있어도 보내며, 열려 있는 화면의 건은 화면이 최신 입력으로 직접 다시 저장한다. 서버 거부(4xx, 401 제외)는 "보내지 못함"으로 남기고 덮어쓰지 않는다. 한계: 화면 파일을 필요할 때 내려받으므로 끊긴 뒤 처음 여는 메뉴는 뜨지 않는다(서비스 워커 없음), 사진·파일 제외, 서버 idempotency 보관은 최근 1만 건, 같은 기록을 두 탭에서 여는 경우는 다루지 않음. 남은 것: 화면 파일 사전 보관(서비스 워커 — 별도 위협모델), 사진, 기기 철회.

- **첫 단위:** 일지 1종만 브라우저 오프라인 초안 → 재접속 시 서버 버전 비교 → 충돌이면 diff 재검토(조용히 덮어쓰지 않음).
- **결정 필요:**
  1. 기기 저장 암호화 방식과 공용 기기 로그아웃 시 삭제 정책(인계: 이것 없이 IndexedDB 저장 금지).
  2. 초안 보존기간.

## ⑤ WEB-01 — 커뮤니티·자료실·배포 목록·뉴스/날씨

**1단계 구현("권장대로"):** 메뉴 "현장 자료실"(현장 구성원 전용). 관리자가 PDF·PNG·JPEG(5MB)를 제목·판 표시와 함께 올릴 때 "저작권·사용 허락 확인" 체크가 필수이고 확인자 이름을 남긴다. 구성원은 미검사 원본을 내려받는다. 삭제 없이 사유 있는 게시 중지만(schema 66 `library_files`). 현장당 200개, 첨부 용량 한도 합산. 외부 공개·뉴스·날씨는 제외.

- **첫 단위:** 현장 내부 "자료실"(관리자 게시, 파일 권리·버전·검역 상태 표시, 구성원 다운로드). 외부 공개 커뮤니티·광고·외부 SDK는 제외.
- **결정 필요:**
  1. 외부 공개 여부(현장 구성원 전용 권장).
  2. 파일 권리 확인 책임자.
  3. 뉴스·날씨 공급원(외부 API, 승인 필요).

## P-02 — 공학 계산

**1단계 구현(2026-10-31 사용자 결정):** 작업계획마다 "장비 계산"(schema 69). 원본 엑셀 수식 중 오류로 확인된 것은 고친 식, 근거를 찾지 못한 계수는 원본 값을 기본으로 두고 직접 바꿀 수 있게 했다. 앱 화면에는 "전문가 검토를 받지 않은 계산" 경고와 계산별 근거 경고를 보이고, 인쇄 계산서에는 넣지 않는다. 아래 원래 차단 조건(독립 전문가 확인)은 여전히 남은 일이다.


인계문서의 차단 근거(계수 0.85/1.3/0.5/1.5/1.4, 고정 1.16, ton/㎡와 kN/㎡ 의미 등)가 **독립 전문가 검토로 확정되기 전에는 구현하지 않는다.** 필요한 것: 검토자, 확정된 식·차원·계수·적용범위, 정상/경계/오류 정답 예제.

## 이 문서가 아닌 것

구현 완료 기록이 아니다. 법적 효력·본인 확인 수준·개인정보 처리 방침을 정하지 않는다.
