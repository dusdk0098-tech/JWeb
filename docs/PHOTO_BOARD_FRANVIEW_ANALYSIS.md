# 사진 보드 개선: 프랜뷰 기능 분석과 Y웹 도입 설계 (2026-11-05)

사용자 요청: "동산보드 폴더의 프랜뷰에서 사진에 보드판 항목·내용을 작성하고, 보드판을 수정·삽입하는 과정, 사진대지 작성과 사진대지 작성[고급]의 기능과 과정을 추적·분석해 Y웹에 도입할 수 있게."

- 대상: `동산보드/프랜뷰.exe` (.NET Framework 4.8 WinForms, x86, 1,336,320바이트, SHA-256 `19c15293a429b788689e748710d900cb0d2d39ad845b8c6c6d72525440086c1b`, MVID `b6187242-894e-4f1e-9a68-e9cc65b15637`). 개인 제작자 배포 프로그램이며 회원 로그인·업데이트 서버와 통신한다.
- 도구: REA `inspect_managed_artifact`(Evidence `ev_825e950f…`), `inspect_managed_members`(Evidence `ev_93b5c114…`). 형식 60개, 메서드 530개, 호출 15,205개, 필드 접근 8,867개, 문자열 799개를 **정적으로** 읽었다.
- **하지 않은 것:** 프로그램 실행·화면 관찰, C# 디컴파일, 내장 엑셀 양식(`Sample.xlsx`)·미리보기 이미지 추출. 그래서 아래 "과정"은 메서드 이름·문자열·호출 순서에서 읽은 것이고, 글자 크기 계산식 같은 세부 수치는 모른다.

## 1. 프랜뷰: 보드판 작성·수정·삽입

화면 하나(`Form_메인`)에서 사진 목록, 보드판 편집, 미리보기, 적용을 한다.

| 단계 | 프랜뷰가 하는 일 (관찰) |
|---|---|
| 사진 불러오기 | 파일·폴더 불러오기, 끌어 놓기, 이름 자연 정렬(1, 2, 10 순), 목록에서 없는 파일 자동 제거 |
| 보드판 항목·내용 | 항목·내용 **2열 표**, 기본 2줄에서 **최대 6줄**까지 [항목 추가]/[항목 삭제]. 줄 높이를 마우스로 끌어 조절 |
| 자주 쓰는 문구 | 칸에서 **F1·F2·F3**를 누르면 문구 목록이 뜬다. 목록 맨 위를 누르면 지금 내용을 그 목록에 저장, 항목을 누르면 커서 위치에 삽입, 우클릭으로 삭제. 같은 키 처리 안에 **오늘 날짜(yyyy.MM.dd)** 를 넣는 동작이 있다(어느 키인지는 미확인). 목록은 `DataResource.Json`에 저장 |
| 모양 | 위치 4곳(좌상·우상·좌하·우하), 크기(슬라이더), 글꼴(설치된 글꼴), 항목·내용 각각 왼쪽/가운데 정렬, 글자 보통/굵게, 테두리 보통/굵게, 글자색·배경색·테두리색, 사용자 색 8개, 투명도, "배경만 투명"(글자는 선명), 글자 높이 보정 |
| 표시 도형 | 사진 위에 **사각형·원**을 그리고 옮기고 크기 조절, 실선/점선, 테두리색 |
| 미리보기 | 지금 설정으로 고른 사진 1장을 그려 보여 줌 |
| 삽입(적용) | [1개] 또는 [전체]: 사진 방향(EXIF) 바로잡기, 너무 작은 사진은 제외, 보드판·도형을 **사진 픽셀에 그려 넣어** 저장 폴더에 새 파일로 저장(같은 이름이 있으면 괄호 번호를 붙이는 것으로 보임), JPEG는 화질 지정. 전체는 진행 창과 [중단] |
| 설정 기억 | 위치·크기·글꼴·정렬·항목 6줄·투명도 등 30여 개를 사용자 설정에 저장해 다음 실행에 복원 |

## 2. 프랜뷰: 사진대지 작성

엑셀을 직접 조종(COM)해 사진대지를 만든다.

1. **[파일 생성]**: 프로그램에 내장된 양식 통합문서를 새 xlsx로 저장. **[파일 불러오기]**: 그 양식인지 시트 19개로 확인.
2. **시트 종류 19가지**: 한 쪽에 1·2·3·4·6·9장, 같은 장수에도 모양 A~G(사진만 / 사진+내용 칸 / 표지형 등). 고르면 미리보기 그림이 바뀐다.
3. **사진 불러오기**: 파일·폴더, **하위 폴더 옵션**(폴더마다 시트 하나, 시트 이름 = 폴더 이름, 31자·`\ / ? * [ ]` 검사).
4. **옵션**: 페이지 자동 맞춤(여백을 늘리고 줄여 쪽 나눔을 맞춤), **파일명 입력**(사진 파일 이름을 '내용' 칸에 — 내용 칸이 있는 양식만), 공백 글자 제외.
5. **작성 순서**: 양식 시트 복사·이름 붙이기 → 사진 수만큼 쪽 틀 복사 → 첫 쪽 머리글(예: 6장-C의 "사 진 대 지 / 공 사 명 / 공 종 명 / 공 사 위 치 / 공 사 일 자")을 **수식으로 다음 쪽들에 연결**(한 번 쓰면 모든 쪽에 반영) → 사진을 칸 크기에 맞춰 삽입 → 파일명 입력 → 인쇄 영역 → 자동 맞춤 → 저장. 단계마다 시각과 함께 작업 기록.

## 3. 프랜뷰: 사진대지 작성 [고급]

이미 열어 둔 **아무 엑셀 파일**에 사진을 꽂는다.

- 작성 종류 3가지: ① **선택한 셀에 사진 1개**, ② **선택한 셀과 같은 크기의 셀에 모두**, ③ **개인 양식에 모두**(인쇄 영역 1쪽을 양식으로 보고 필요한 만큼 쪽을 늘림).
- 맞춤: 칸 채우기(Full) / 비율 유지(Ratio). 옵션: **다음 셀로 이동**(인쇄 영역 안에서 다음 같은 크기 병합 셀 선택), 넣은 사진을 목록에서 삭제, 창 항상 위, 페이지 자동 맞춤, 사진 여백 조정.
- 조건: 병합된 셀이어야 하고 인쇄 영역이 있어야 하며, 칸이 모자라면 못 넣은 사진 목록을 알려 줌.

## 4. Y웹 사진 보드와 비교

| 기능 | 프랜뷰 | Y웹 지금 | 도입 판단 |
|---|---|---|---|
| 보드판(항목·내용 표를 사진에 얹기) | 있음, 6줄·위치·모양 다양 | **없음**(보드 정보는 인쇄 머리글에만) | **도입(핵심)** |
| 자주 쓰는 문구·오늘 날짜 | F1~F3, 날짜 키 | 없음 | 도입(현장별 문구 목록) |
| 표시 도형 | 사각형·원, 실선·점선 | 원(3색) | 사각형·점선 추가 |
| 여러 장에 한 번에 적용 | 전체 적용 + 중단 | 없음 | 도입(같은 보드판을 여러 장에) |
| 원본 보존 | 새 파일로 저장 | 원본 보존, 화면용 사본 | Y웹 방식 유지(원본에 굽지 않음) |
| 사진대지 양식 | 19종(1~9장, 내용 칸) | 고정 배치 1종 | 도입(장수·내용 칸 선택) |
| 머리글 한 번 입력→모든 쪽 | 공사명·공종명·위치·일자 | 현장명·작업내용 등 | 공사 머리글 4칸으로 정리 |
| 파일명→내용 칸 | 있음 | 사진 설명 칸 | "설명이 비면 파일명" 옵션 |
| 폴더별 시트 | 하위 폴더 = 시트 | 폴더 올리기 있음 | 폴더 이름으로 묶어 쪽 나누기 |
| 엑셀(xlsx) 결과 | 엑셀 필수 | PNG·인쇄/PDF | **1차는 인쇄/PDF**, xlsx는 2차(의존성 승인 필요) |
| [고급] 아무 엑셀에 꽂기 | 열린 엑셀 조종 | 불가 | 웹에서는 불가 → "칸 직접 고르기"로 대체 |

## 5. Y웹 도입 설계

원칙: 원본 사진은 그대로 두고, 보드판·도형은 **장면(scene) 데이터**로 저장해 화면·PNG·인쇄가 같은 그리기 함수(`src/photo-scene.ts`)를 쓴다(지금 원·확대와 같은 방식).

### 5.1 데이터

```ts
// 보드 전체에 하나(모든 사진에 같은 보드판). 사진마다 다르게 쓰려면 item.board로 덮어쓰기.
type BoardPanel = {
  rows: { label: string; value: string }[];        // 1~6줄
  corner: "tl" | "tr" | "bl" | "br"; size: number;  // size: 사진 짧은 변 대비 비율
  align: { label: "left" | "center"; value: "left" | "center" };
  bold: boolean; border: "normal" | "thick";
  colors: { text: string; fill: string; line: string }; opacity: number; fillOnly: boolean;
};
type Shape = { kind: "circle" | "rect"; x: number; y: number; w: number; h: number; color: string; dashed: boolean };
// Scene: layoutVersion 2 — board?: BoardPanel, items[].board?: BoardPanel, items[].shapes (circles → shapes로 이전)
```

- 현장별 **자주 쓰는 문구**: 새 테이블 `phrase_presets(site_id, slot 1~3, text, …)`. 문구 칸에서 단축키·버튼으로 목록 열기, 오늘 날짜 넣기.

### 5.2 화면

- 편집 화면 오른쪽에 **보드판** 묶음: 줄 추가·삭제(최대 6), 항목·내용 칸, 위치 4칸 버튼, 크기·투명도 슬라이더, 정렬·굵기·테두리·색.
- **"모든 사진에 같은 보드판"** 기본, 사진별로 "이 사진만 다르게".
- 도형 도구: 원 / 사각형, 실선 / 점선.
- 내보내기: 보드판이 그려진 사진을 **장별 JPEG(ZIP)** 로 받기(원본과 별도), 기존 PNG·인쇄 유지.

### 5.3 사진대지 출력(인쇄/PDF)

- 쪽당 **1·2·3·4·6·9장**, "내용 칸" 있음/없음, 표지형(머리글 표) 선택.
- 머리글 4칸(공사명·공종명·공사 위치·공사 일자)을 보드에 한 번 쓰면 모든 쪽에 찍힘.
- 내용 칸: 사진 설명, 비어 있으면 파일명(옵션).
- 폴더로 올린 사진은 폴더 이름으로 묶어 묶음마다 새 쪽에서 시작(옵션).
- [고급] 대체: 인쇄 배치 미리보기에서 **칸을 눌러 사진 넣기**, 다음 빈칸으로 자동 이동, 칸 채우기/비율 유지.

### 5.4 하지 않을 것

- 열린 엑셀 조종, 사용자의 개인 엑셀 양식에 꽂기(브라우저에서 불가).
- 원본 사진에 보드판을 굽기(원본 보존 원칙). 구운 사진은 내려받기용 사본으로만 만든다.
- 회원·워터마크·업데이트 서버.
- xlsx 출력은 라이브러리 추가(의존성 승인)가 필요해 2차로 미룬다.

## 6. 작업 순서 (PR 단위)

| # | 내용 | 검증 |
|---|---|---|
| 1 | 보드판: scene v2(board, shapes), 그리기 함수, 편집 묶음, 모든 사진 적용·사진별 덮어쓰기, PNG·인쇄 반영, 기존 원 데이터 이전 | 단위(그리기 좌표·이전), E2E(보드판 작성→인쇄에 표시) |

### 진행 (2026-11-11)

1단계는 PR #105·#107, 2~5단계는 한 PR로 구현했다. 설계와 달라진 점:

- **2단계 도형:** scene `layoutVersion`을 올리지 않았다. 기존 `circles` 배열의 강조에 선택 필드(`kind: "rect"`, `h`, `dashed`)를 더해 저장된 원 강조가 그대로 유효하다. 강조를 만든 뒤 모양·점선을 바꾼다.
- **3단계 문구:** `phrase_presets` 테이블 대신 **이 기기의 localStorage**에 현장별로 보관한다(프랜뷰도 PC에 보관). 보드판·머리글을 저장하면 그 내용이 문구로 남고, 내용 칸의 브라우저 제안 목록(datalist)에 오늘 날짜와 함께 뜬다. 목록 3개·단축키는 만들지 않았다. 여러 사람이 한 목록을 써야 하면 현장 테이블로 옮긴다.
- **4단계 사본:** 포함한 사진마다 회전·확대·강조·보드판을 그린 JPEG를 만들어 무압축 ZIP 하나로 받는다(브라우저에서 생성, 의존성 없음). 크기는 표시본에서 보이는 부분의 픽셀이다. 원본에는 굽지 않는다.
- **5단계 양식:** 쪽당 1·2·3·4·6·9장, 내용 칸 켜기/끄기, 머리글 4칸(공사명·공종명·공사 위치·공사 일자), "설명이 비면 파일명". 보드에 저장하며, 양식을 켜지 않은 보드는 기존 2장 인쇄 그대로다. **하지 않은 것:** 폴더 이름으로 묶어 쪽 나누기(사진에 폴더 정보가 저장되지 않음), 칸 직접 고르기(지금은 순서 이동으로 대신), 표지형, xlsx 출력.

## 7. 확인하지 않은 것

- 프랜뷰를 실제로 실행해 화면을 보지 않았다. 버튼 배치, 단축키 번호(날짜 키), 크기·글자 높이 계산식은 정적 정보로 알 수 없다.
- 19개 양식의 칸 크기·모양은 이름(장수·A~G)과 인쇄 영역 범위만 보았다.
- 실행해 보고 싶으면 사용자가 직접 프랜뷰를 켜고 같은 작업을 해 보며 화면을 보여 주는 방식이 가장 안전하다.
