# 이 PC를 서버로 쓰기 (외부 접속)

Y웹을 설치한 PC가 그대로 서버가 되어, 휴대폰·다른 PC에서 직접 산 도메인(예: `https://safety.example.com`)으로 접속하게 하는 방법이다. **서버와 데이터베이스는 이 PC에만 있다.** 개발자나 다른 회사의 서버에 현장 데이터를 두지 않는다.

- 이 PC가 켜져 있고 앱이 실행 중일 때만 밖에서 접속된다.
- 꺼 둔 상태(기본)에서는 지금처럼 이 PC(`http://127.0.0.1:3000`)에서만 열린다.
- 밖에 열면 누구나 로그인 화면에 닿는다. 모든 계정에 12자 이상의 강한 비밀번호를 쓰고, 쓰지 않는 계정은 지운다. 로그인은 계정별·접속 주소별로 15분에 실패 10회·30회에서 막힌다.
- AI 공용 키와 외부 접속 설정 같은 PC 공용 설정은 밖에서 접속하면 보이지도, 바뀌지도 않는다.
- 설정은 **이 PC에서 직접 접속한 운영자**만 바꿀 수 있다.

## 1. 마법사로 연결하기 (권장)

홈 화면의 외부 접속 상태 줄에서 **외부 접속 설정 열기**를 누르거나, 설정 → **외부 접속 설정** → **도메인 연결 시작**을 누른다.

1. **Cloudflare Tunnel로 시작한다.** 무료이고 공유기·방화벽을 건드리지 않아 대부분의 사무실·현장에서 그대로 된다(사용자 결정 2026-11-02). Cloudflare를 거치지 않기를 원하고 공유기 설정을 바꿀 수 있다면 마법사 위의 **고급: 다른 방식**에서 **직접 연결 + 자동 HTTPS**를 고른다.
2. **단계를 위에서부터 따라간다.** 단계마다 상태(완료 · 아직 안 됨 · 확인 불가 · 확인 중)와 이유가 보인다. 다른 곳에 입력할 값과 명령은 **복사** 버튼으로 가져간다. 손으로 옮겨 적을 값은 없다.
3. **앱이 대신 할 수 있는 일은 버튼 하나로 한다.**

   | 단계 | 버튼 | 앱이 하는 일 |
   |---|---|---|
   | 공유기 포트포워딩 | 공유기에 80·443 열기 | 공유기 자동 설정(UPnP)으로 80·443을 이 PC로 연다 |
   | DNS (직접 연결) | A 레코드 만들기 | DNS가 Cloudflare에 있으면 A 레코드를 만든다 |
   | Cloudflare 터널·DNS | Cloudflare에 만들기 | 터널·연결 설정·DNS를 만든다 |
   | Windows 방화벽 | 관리자 권한으로 실행 | 화면의 명령 하나를 실행한다. Windows 권한 확인 창에서 ‘예’를 눌러야 실행된다 |
   | cloudflared 설치 | 관리자 권한으로 실행 | `winget`으로 설치한다(1~2분) |

   버튼이 실패해도(공유기가 자동 설정을 지원하지 않음, 회사 PC라 관리자 권한이 막힘 등) 같은 자리에 직접 할 때 필요한 값과 명령이 그대로 남는다.
4. **모든 단계가 ‘완료’가 되면 적용한다.** `start.cmd`로 켠 앱은 **다시 시작해 적용** 한 번으로 끝난다. 다른 방법으로 켰다면 **설정 적용** 후 앱을 직접 다시 시작한다. 다시 켜진 뒤 앱이 자기 주소로 접속해 보는 **적용 확인**이 나온다. 직접 연결에서 "확인 불가"가 나오면 공유기가 내부 접속을 막는 경우가 많으니 휴대폰(LTE)으로 확인한다.

앱 밖에서 해야 하는 일은 많아야 두 가지다.

- **Cloudflare Tunnel(기본)**: Cloudflare 무료 계정 만들기·도메인 추가(네임서버 변경), API 토큰 만들기. 토큰 권한은 마법사 화면의 **필요한 권한**을 복사해 고른다: Account › Cloudflare Tunnel › Edit, Zone › DNS › Edit, Zone › Zone › Read. 대상 영역은 이 도메인만 고른다. 터널 기능만 쓰므로 Zero Trust의 사용자 수 한도(로그인 보호 기능용)와는 상관없다. 처음 Zero Trust를 켤 때 결제 수단 등록 화면이 나올 수 있지만 무료 플랜은 청구되지 않는다.
- **직접 연결(고급)**: 도메인 회사의 DNS에 A 레코드 값 입력(DNS가 Cloudflare면 앱이 대신 함), 공유기가 자동 설정을 지원하지 않으면 포트포워딩.

**도메인이 없다면** 먼저 도메인 등록 대행사에서 산다(보통 1년 단위). DNS 레코드를 직접 편집할 수 있는 곳이어야 한다. 앱은 도메인을 팔거나 대신 발급하지 않는다.

### 연결한 뒤

- 설치 PC의 운영자 홈에 **외부 접속 상태 한 줄**이 보인다: 정상(주소·인증서 만료일), 연결 중, 멈춤(이유), DNS 어긋남. 옆의 **외부 접속 설정 열기**를 누르면 마법사가 고칠 단계로 바로 이동한다.
- 직접 연결로 실행 중에는 **10분마다** 앱이 확인한다.
  - 공유기 자동 설정(UPnP)으로 연 80·443을 다시 연다(공유기 재부팅 대비). 지원하지 않는 공유기면 아무 일도 하지 않는다.
  - 회선의 공인 IP가 바뀌어 도메인이 옛 주소를 가리키면, 마법사에 넣은 Cloudflare 토큰이 이 도메인 것일 때 A 레코드를 새 IP로 고친다. 아니면 홈에 바뀐 IP와 할 일을 보여 준다.

## 2. 외부로 나가는 요청

마법사와 감시는 아래 상대에게만 요청한다. 현장·계정·사용 기록은 보내지 않는다.

| 상대 | 언제 | 보내는 것 |
|---|---|---|
| 공유기(사내망) | 공유기 자동 설정, 공인 IP 확인 | 이 PC의 내부 IP와 포트 |
| `www.cloudflare.com/cdn-cgi/trace` | 공유기가 공인 IP를 알려 주지 않을 때 | 요청 자체(이 PC의 공인 IP가 보임) |
| `api.cloudflare.com` | 토큰 확인, 터널·DNS 생성, A 레코드 고침 | API 토큰, 도메인, 터널 이름 `yweb-도메인`, 서비스 주소 `http://127.0.0.1:포트`, 공인 IP |
| Let's Encrypt 시험 서버(staging) | 공유기 단계의 "밖에서 닿는지" 시험 | 도메인(시험용 계정 키는 따로 보관, 받은 시험 인증서는 버림) |
| Let's Encrypt | 적용 후 실제 인증서 발급·갱신(직접 연결) | 도메인, 인증서 알림 이메일 |

**Cloudflare Tunnel을 고르면** 휴대폰과 이 PC 사이의 접속 내용이 Cloudflare 서버를 거친다(그곳에서 암호화가 풀렸다가 다시 걸린다). 데이터는 이 PC에만 저장되지만, 제3자를 거치는 것이 싫다면 직접 연결을 쓴다.

## 3. 알아 둘 점

- 저장된 터널 토큰·Cloudflare API 토큰·AI 키는 `.env`의 `SESSION_SECRET`으로 암호화된다. `SESSION_SECRET`을 바꾸면 다시 입력해야 한다. 토큰은 화면에 다시 보이지 않는다(끝 4자리만).
- TBM 참여 QR은 외부 접속이 켜져 있으면 공개 도메인 주소로 만들어진다. 꺼져 있으면 이 PC에서만 열리는 주소이며 화면에 그렇게 표시된다.
- 재부팅 뒤 서버를 저절로 켜려면 프로젝트 폴더의 `autostart.cmd`를 한 번 실행한다(시작프로그램 폴더의 바로 가기 하나, 관리자 권한 없음, 다시 실행하면 끔). Windows에 로그인해야 켜지므로, 사람이 없는 PC라면 Windows 자동 로그인 여부는 운영자가 따로 정한다. 앱이 이 바로 가기를 스스로 만들지는 않는다.
- 이 PC가 서버이므로 정전·재부팅·절전 때는 접속이 끊긴다. 백업(`npm run backup:local`)과 데이터 폴더 권한 정리(`npm run secure-data -- --apply`)를 먼저 해 둔다.
- 앱이 Windows 설정을 바꾸는 것은 **관리자 권한으로 실행** 버튼을 누르고 Windows 권한 확인에서 ‘예’를 누른 경우뿐이며, 화면에 보인 명령 두 가지(방화벽 80·443 허용, cloudflared 설치)만 실행한다.
- 실제 도메인으로 인증서 발급·터널 연결을 해 본 기록은 아직 없다. 자동 시험은 가짜 공유기·DNS·인증기관·Cloudflare·cloudflared로 했다([PC 검증 기록](PC_VALIDATION.md)).

### A. 직접 연결 + 자동 HTTPS

1. **도메인 DNS**: 도메인을 산 회사의 DNS 관리에서 A 레코드(예: `safety` → 이 사무실의 공인 IP)를 만든다. 공인 IP는 공유기 관리 화면에서 확인한다. 공인 IP가 바뀌는 회선이면 공유기의 DDNS 기능이나 B 방식을 쓴다. DNS가 Cloudflare에 있으면 그 레코드의 프록시(주황 구름)는 끈다(회색 구름). 켜져 있으면 인증서 발급 확인이 이 PC까지 오지 않는다.
2. **공유기 포트포워딩**: 외부 TCP 80, 443을 이 PC의 내부 IP 80, 443으로 보낸다. 80은 인증서 발급 확인과 https 이동에만 쓴다. 메뉴 위치는 기종·펌웨어마다 다를 수 있다.

   | 공유기 | 메뉴 위치(대표) |
   |---|---|
   | ipTIME | 관리도구 → 고급 설정 → NAT/라우터 관리 → 포트포워드 설정 |
   | ASUS | 고급 설정 → WAN → 가상 서버 / 포트 포워딩 |
   | TP-Link | 고급 → NAT 포워딩 → 가상 서버 |
   | Netgear | 고급 → 고급 설정 → 포트 포워딩/포트 트리거링 |
   | 통신사 임대(KT·SK·LG U+) | 기종마다 관리 주소·메뉴가 달라 통신사 고객센터에 "포트포워딩 80·443"을 요청 |

3. **Windows 방화벽**: 관리자 PowerShell에서 실행한다.
   ```powershell
   New-NetFirewallRule -DisplayName "Y웹 HTTP/HTTPS" -Direction Inbound -Protocol TCP -LocalPort 80,443 -Action Allow
   ```
4. **앱 설정**: 고급: 직접 입력 → 방식 "직접 연결 + 자동 HTTPS", 도메인, 인증서 알림 이메일 입력, Let's Encrypt 이용약관 동의 → 저장. 화면의 "DNS 조회 결과"에 공인 IP가 보이면 DNS가 준비된 것이다.
5. **앱 다시 시작**: 시작하면서 인증서를 받는다(수십 초). 상태가 "실행 중"이 되면 휴대폰에서 `https://도메인`으로 접속해 확인한다. 실패하면 이유가 설정 화면과 콘솔 창에 나온다(대부분 DNS 전파 전이거나 80 포트가 막힌 경우).

인증서와 계정 키는 `data/tls/`에 저장된다(`TLS_DIR`로 변경 가능). 공유기가 외부 80/443을 다른 내부 포트로 보내야 하면 `.env`에 `PUBLIC_HTTP_PORT`, `PUBLIC_HTTPS_PORT`를 지정한다.

### B. Cloudflare Tunnel

1. Cloudflare 무료 계정을 만들고 도메인을 추가한다. 도메인 회사에서 네임서버를 Cloudflare가 알려 준 값으로 바꾼다.
2. Cloudflare 대시보드 → Zero Trust → Networks → Tunnels → 터널 만들기(Cloudflared). 설치 안내 화면의 명령에 들어 있는 토큰(`eyJ…`)을 복사한다.
3. 터널의 Public Hostname: 하위 도메인/도메인을 정하고, Service는 `HTTP` / `127.0.0.1:3000`. DNS 레코드는 Cloudflare가 자동으로 만든다.
4. 이 PC에 cloudflared 설치(관리자 권한 필요할 수 있음):
   ```powershell
   winget install --id Cloudflare.cloudflared
   ```
   다른 위치에 설치했다면 `.env`에 `CLOUDFLARED_PATH`를 지정한다.
5. 앱 설정: 고급: 직접 입력 → 방식 "Cloudflare Tunnel", 도메인, 터널 토큰 → 저장 → 앱 다시 시작. 앱이 cloudflared를 직접 실행하고 끊기면 다시 연결한다. 토큰은 암호화해 저장하고, 실행할 때 환경 변수로만 넘긴다.

## 4. 근로자 QR 가입 (2026-11-05)

- 현장 관리자는 **현장 관리 → 근로자 가입 QR**에서 1일·7일·30일짜리 가입 QR을 만든다. QR을 찍은 사람은 이름·생년월일 6자리·소속을 넣고 동의·서약에 체크하면 바로 그 현장의 작성자로 들어온다. 승인 단계는 없다(사용자 결정).
- 근로자는 로그인 화면의 **근로자** 탭에서 이름과 생년월일로 로그인한다. **이름과 생년월일을 아는 사람은 그 근로자로 로그인할 수 있다**(사용자가 이 위험을 알고 고른 방식). 실패는 이름별로 15분에 10번까지다. QR은 짧게 두고 다 쓰면 회수한다.
- 생년월일은 솔트를 섞은 해시로만 저장한다. 주민등록번호는 받지 않는다(법령 근거 없이 처리할 수 없고 저장 시 암호화·유출 책임이 생김). '내 정보'는 생년월일을 다시 넣어야 10분 동안 열린다.
- 같은 이름·생년월일은 같은 사람으로 보고, 다른 현장 QR로 가입하면 그 현장만 추가된다. 동명이인이 생일까지 같으면 한 계정이 된다.
- 동의·서약 문구(`server/consent-text.ts`의 `SIGNUP_CONSENT`)는 **개발자 초안**이다. 실제로 쓰기 전에 운영자나 법률 검토자가 확인한다.

## 5. 현장 관리자 가입 신청 (2026-11-05)

- 로그인 화면의 **현장 관리자 가입 신청**에서 이름·아이디(영문 소문자·숫자 4~30자)·비밀번호(12자 이상)·소속·맡을 현장 이름을 넣고 동의·서약에 체크해 신청한다. 승인 전에는 계정이 없다.
- 운영자는 이 PC에서 **계정 발급 → 관리자 가입 신청**에서 기존 현장을 고르거나 새 현장을 만들며 승인하고, 사유를 적어 반려한다. 홈에도 "관리자 가입 신청 N건"이 보인다. 반려하면 저장해 둔 비밀번호 해시를 지운다.
- 승인된 관리자는 아이디(또는 이메일)와 비밀번호로 로그인한다. 신청은 전체 15분 20건, 대기 50건까지 받는다.
- 근로자 계정은 현장을 새로 만들 수 없다. 동의 문구(`MANAGER_SIGNUP_CONSENT`)는 개발자 초안이다.
