# 앱 전체 검토 (2026-11-02)

세 갈래로 봤다. (1) 합성 서버에서 처음 쓰는 사람의 순서로 직접 눌러 본 사용 흐름(PC 1280·폰 375, DOM 측정), (2) 화면 62개·서버 라우트 411개 코드 감사, (3) 국내 스마트 안전관리 앱 7종·고용노동부/KOSHA 도구·글로벌 앱·법규 웹 조사. 실제 현장 사용자 인터뷰는 없다. 시장 "안 쓰는 기능" 통계도 1차 자료는 확인하지 못했다(추정으로 표시).

## 0. 결론 한 장

- **기능은 충분히 많다. 부족한 것은 "덜 보이게·덜 입력하게·이어지게"다.** 화면 62개, 미사용 서버 라우트 0개. 그런데 같은 일을 하는 입구가 여러 개(내 할 일 5곳, 위험성평가 목록 2곳, 사진 3벌), 확정 동사가 8가지, 날짜·작성자 기본값이 비는 곳이 10곳 이상이다.
- **법정 서류 쪽에 구멍 3개**: 사고·아차사고 기록(산업재해조사표, 3년 보존), 작업허가서(화기·밀폐·고소, 1년 보존), 근로자별 교육·자격 이수 추적. 모두 기존 모듈을 조금 넓히면 된다.
- **제거 후보는 많지 않다.** 통합이 맞는 것(공지↔자료실, 최소재고 입구 2개, 소속 입력 2곳)과 접어 둘 것(양중 계산, 위험성평가 도구 5개)이 대부분이다. 삭제하면 데이터가 사라지는 것은 없다.

## 2. 보완 — 끊긴 연결 (감사 4절)

- 신고 → 조치 → 작업 중지·재점검·위험성평가 조치로 이어지지 않는다. 신고 종결 화면에 "작업 중지 기록 만들기 / 재점검 일정 잡기" 버튼 하나면 된다.
- TBM → 교육일지, 위험성평가 → 작업계획, 장비 사용기록 → 작업계획이 서로 모른다. 작업계획의 위험요인은 사용자가 올린 파일이다. 평가 문서의 위험행을 작업계획·TBM에 **불러오기**(국내 앱 7종이 모두 핵심으로 홍보하는 기능).
- 일지 "오늘 요약"에 신고·TBM·작업 중지·교육·장비가 안 들어간다(날짜 필터 없음).
- 회의 후속조치는 읽기 전용 보드. 처리하려면 세 번 이동.
- 명부 "소속" 자유 입력과 업체 연결이 따로여서 같은 사실을 두 번 적는다.

5. **통합·축소**: 공지·자료·회의록, 내 할 일, 위험성평가 고급 접기, 소속 입력.
6. **그 다음**: 서류 묶음 출력, 다국어 TBM, 폭염 기록, CSV.

## 결정이 필요한 것

- D1 확정 동사 3개(저장·제출·확정)로 통일할지 — E2E 40여 곳 라벨 수정이 따라온다.
- D2 범용 재고를 축소할지, 두고 보호구만 앞세울지.
- D3 공지·자료·회의록 통합 여부.
- D4 법정 3종(사고·작업허가·이수 추적) 추가 여부와 순서.
- D5 다국어·폭염은 외부 API(AI·기상청)를 쓰므로 "외부 요청 표"에 추가 고지 필요 — 넣을지.

## 확인하지 않은 것

실제 현장 사용자 반응, 네이버 카페·블라인드 1차 후기, 교육일지 보존기간·폭염 기록 보관 의무의 정확한 조문, 중처법 시행령 원문(법률 칼럼 2차 자료), Capterra·G2 원문(검색 요약). 코드 감사는 정적 읽기라 버튼 글자 한두 개가 빠졌을 수 있다. 브라우저는 창이 그려지지 않아 스크린샷 대신 DOM 측정으로 봤다.
